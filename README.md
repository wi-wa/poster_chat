# Annulus Poster Site

Static GitHub Pages site with a five-button menu opening Chat, Contingent Knowledge Eval, Benchmarks, Handlabeled Viewer, and Data Viewer SFT. The eval model selector generates downloadable PNG comparisons in the browser. Chat uses the public API endpoint in `site.json`; the data views work independently of the inference server. `data.html` redirects to the SFT viewer so existing links and QR codes still work.

Run `python3 scripts/export_data.py --source ../mwdf --eval-only` to refresh contingent knowledge and GSM8K without changing the other snapshots. Both datasets have selectable model comparisons, sampled responses, reasoning, and scoring explanations. The current export covers 100 contingent-knowledge questions and 128 GSM8K test questions, with 2 responses per question for each of twelve 7B checkpoints: exp, reif and control after SFT, DPO, SFT v2 and RL v2. SFT v2 and RL v2 were trained without reasoning, so they answer without thinking; the others think first. The benchmarks table is left as it is while mwdf's `artifacts/evals/final` is missing. Knowledge is LLM-judged; GSM8K uses normalized numeric exact match on the visible final answer.

Omit `--eval-only` to also refresh the training-data snapshots. The exporter validates the saved manifests, question-bank hashes, per-model summaries, and comparisons before publishing evaluation data. It samples 100 synthetic conversations deterministically and copies the hand-label data and full-corpus normalization statistics. `src/viewer` reuses the source viewer's calculations; only its corpus URL and presentation are adapted for the public snapshot. No private chat conversations are exported.

Local preview: `python3 -m http.server 8770 --bind 127.0.0.1`, then open `http://127.0.0.1:8770/`.

On birget, `bash scripts/start_chat.sh` starts the `chat_gradio` tmux session if it is missing: the poster launcher (`scripts/serve.py`) serves port 8770 and proxies the chat API through Gradio. The inference server sleeps until someone presses WAKE UP on the chat page. `serve.py` then runs `scripts/start_inference.sh` on the lowest-numbered GPU with 72 GB free, in tmux session `chat_inference_server`, and the page shows its startup log (`.gradio/inference_server.log`) until it answers, in 1-2 minutes (a few more after a code change, while it compiles). It serves fifteen 7B checkpoints on port 8400, per arm the SFT and DPO iteration-1 models, SFT v2, RL v2 and no-identity SFT v2 (API models `annulus-7b-<arm>-sft`, `-dpo`, `-sft_v2`, `-rl_v2`, `-sft_v2_noidentity`; the chat page picks one), and each one's Jacobian lens from mwdf `artifacts/jlens` (`POST /v1/jlens`, documented on the `/api` page). The chat page's J-lens checkbox shows the conversation's tokens as the selected model saw them in its latest reply; clicking one lists the top 10 tokens of the lens readout at that token, averaged over the chosen layers, with each layer's top 5 and the model's own next-token prediction. The Steer checkbox steers replies and readouts with tokens' J-lens vectors: each token (typed, or added with + from the J-lens box) and its signed strength, a fraction of each block's typical output norm, shift the outputs of a range of blocks (default 4-8) while the model reads and writes (`steering` in the API). Everything runs on that one GPU: only the first model loads at startup, the others load into host memory in the background (from mwdf `.chat_weight_cache`, a few seconds each), and the two most recently used models and the two most recently read 7.7 GB lenses stay on the GPU, so switching models or lenses takes a few seconds. The server goes back to sleep after 30 minutes without chat completions or J-lens requests through the proxy (`serve.py --idle-sleep-minutes`, 0 disables; requests straight to port 8400 do not count). Start it by hand with `scripts/start_inference.sh [GPU]`; put it to sleep with `tmux kill-session -t chat_inference_server`. `GET /power` reports asleep, starting or awake and `POST /power/wake` wakes it. Its environment is `/data/students/wiwal2741/venvs/chat-gradio` (Gradio 6.26.0). Keep the ignored `.gradio/share-token` private: it reuses the existing tunnel identity. Confirm the printed Gradio URL matches `site.json` after restarting; share links are temporary. These sessions survive terminal disconnects, not host reboots.

Checks: `python3 -m unittest discover -s scripts -p 'test_*.py'`; with Playwright installed and the preview running, `node scripts/test_site.cjs`. The browser checks mock inference (chat, wake-up and the J-lens view) and write screenshots to `/tmp/poster-chat-screenshots`. Optional environment variables: `SITE_URL`, `CHROMIUM_PATH`, `SCREENSHOTS`.
